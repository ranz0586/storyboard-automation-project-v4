Production briefs — Vercel port, 2026-10-21

Open a project's Settings → Production brief. Set narration language (up to 100 characters), a whole-second target duration of 5–300 seconds, and optional character/style descriptions (up to 3,000 characters each). Blank language uses project context; blank duration lets the script choose its length. Blank descriptions add no reference directions. Choose any nonempty combination of the three storyboard outputs and save. Workflow remains narrated video, starting with project research/ideas and narration audio; unsupported workflows, inputs and audio modes are rejected.

The editor extends the existing output-selection/guidance card. It retains unsaved edits across tabs, reloads persisted defaults, supports retry after read failure, and disables editing while saving or when the project is inactive. Script details show the frozen language, planning duration, descriptions, outputs and guidance versions. Saved storyboard JSON/readers/exports retain the complete frozen production_brief.

Defaults apply to items that have not started generation. Before the first Script provider call, the shared worker freezes the brief, project identity/assets and guidance versions. Failed runs, recovery, scheduled runs and cloud replay use the same immutable item snapshot. Writer, both permitted validation attempts and storyboard conversion receive the snapshot through existing prompts; no agent stage or dependency is added. Existing factual/editorial acceptance, scene timing, human approval and cloud leases/checkpoints/cooldowns remain authoritative. Original system.js files and the four versioned guidance pack texts are unchanged.

Duration is a planning target, not an exact-length promise or permission to stretch scenes. Language is a generation instruction, not a measured TTS guarantee. Storyboards preserve the approved Script's actual narration/language and timeline. Text descriptions guide visual prompts; they neither attach images nor prove image approval. Mixed-duration repair, plan auditing, alternate inputs and measured media/analytics are separate work.

Compatibility and storage:

- The existing app_project_briefs and app_item_briefs JSON payloads hold the new fields; no additional SQL or Airtable schema changes are needed beyond the two-table migration already required by output selection. Run npm run db:migrate before deploying that combined feature if it has not been applied. This implementation did not apply a live migration.
- Existing selection-only project defaults gain safe empty/null/fixed-mode defaults on read. PUT requests merge only supplied validated fields, so an older selection-only client cannot erase newer language/reference settings. Local updates use the existing locked JSON transaction; PostgreSQL updates merge JSON atomically to preserve concurrent updates to different fields. Explicit empty strings/null clear optional values.
- Existing item snapshots are returned exactly as saved, including selection-only snapshots without the new fields. They are never silently rewritten or enriched with current defaults. The Script display labels missing legacy language/duration as Not recorded. Existing legacy cache/provenance rules remain as described in output-selection-and-guidance.md.
- Drain active generation jobs before switching prompt versions. Rollback restores the prior build after draining and retains additive tables and snapshots; do not delete frozen records to retry. Local operators still use BRIEF_STATE_PATH; the separate localhost source checkout was not edited or imported.
