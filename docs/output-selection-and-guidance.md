Output selection and creative guidance — Vercel port, 2026-10-21

**Operator behavior**

Open Settings → Production brief → Storyboard outputs. Choose any nonempty combination of Structures 1, 2 and 3, or Select all; then Save production brief. New projects default to all three formats. An empty/duplicate/unknown selection is rejected. The subsequent [Production briefs port](production-briefs.md) adds language, duration and reference descriptions to this same editor.

The built-in guidance covers truthful openings, editorial clarity, visual continuity and feasible motion. The four repository-owned packs retain their reviewed localhost version IDs: truthful-hooks@1, editorial-clarity@1, visual-continuity@1 and motion-endpoints@1. They are original concise adaptations described in the localhost creative-guidance source inventory, not runtime loading of installed Codex skills/tools. Source adaptation, blueprint and What If guidance is not ported here. No runtime KOS files, tool access, new dependency or extra Gemini stage is introduced. Prompt size grows; no cost/quality improvement is claimed from mock tests.

**Freeze and retry contract**

Project defaults and per-item snapshots are separate. The shared Script worker freezes selection, guidance IDs, project/audience/channel identity and character/style reference values under its existing item lock before its first provider call. Manual, full-pipeline, scheduled, recovery and cloud execution use that worker. Defaults edits apply to items that have not started; failed generation and retries retain the first snapshot. Writer and both allowed validation attempts receive role-specific guidance from the same snapshot. Factual evidence, hook/payoff/originality, scene timing, manual approval and two-call validation limits remain unchanged. Original system.js messages are unchanged; selection is an additive explicit wrapper, guidance is added to user prompts.

Storyboard conversion reads that same snapshot. Every requested format must be nonempty and independently cover the entire approved Script with unchanged narration and timing. Provider surplus in unselected structures is removed before parsing/persistence; missing selected output is rejected. Structure 2 alone uses ordered integer scene references and matching panel ranges without a hidden Structure 1/3 requirement. The existing Vercel clock-string/frame contract remains canonical; numeric-timeline migration and mixed-duration Script repair are separate work.

New storyboard JSON embeds the frozen production_brief. Existing structure1_json/structure2_json/structure3_json remain; unselected arrays are empty, and structure_type matches the available output. All Airtable writes retain existing typecast/upsert behavior. No Airtable columns, tables or lifecycle statuses are added. Script details show frozen outputs/guidance; saved storyboard readers/exports preserve snapshot metadata.

Usable legacy Scripts remain reusable without retroactively claiming new guidance. A valid cached legacy storyboard with no snapshot remains reusable under the existing Vercel fidelity gate, even if current defaults select another format. A first new storyboard conversion for an older Script freezes current output settings with origin legacy-storyboard, explicitly describing conversion settings rather than claiming the original Script used them. Already Story Generated work is unchanged. No bulk migration/regeneration occurs.

**Storage and deployment**

- Cloud: `src/cloud/briefStore.js` uses server-only `app_project_briefs(project_key,payload)` and `app_item_briefs(project_key,item_id,payload)`. Unique item identity and first-writer-wins insertion preserve immutable snapshots across independent function instances. RLS and anonymous/authenticated client-table revocations follow existing runtime state protection. Credentials remain server-only; Airtable remains the content/account database.
- Local Express/operators in this Vercel checkout: `BRIEF_STATE_PATH` defaults to `data/briefs.json`. Preserve/back up it with run/schedule files and use the same absolute path across local processes. State recovery includes it and still requires stopped servers. The separate localhost checkout was not edited or imported.
- Async APIs: authenticated GET/PUT `/api/projects/:id/brief` expose validated brief defaults and read-only guidance IDs; the Production briefs follow-up adds the remaining fields. Existing ownership, same-origin, throttling and active-project write checks apply. Script collection responses optionally include the item's productionBrief. APIs and workers await both file and database stores; Vercel never constructs a local brief store.
- Cloud clients inject the database store and retain lease guards, shared key cooldowns, provider checkpoints and DEFERRED behavior. Stable frozen prompt input lets successful model responses replay without new calls after a lost Script save.

Before deployment, run `npm run db:migrate` with the existing DATABASE_URL or SUPABASE_POOLER configured privately. This creates two additive app-state tables; no new cloud key/provider is needed. The schema is repeatable and preserves settings/snapshots. No live database migration was executed for this implementation. New endpoints/jobs fail visibly if tables are missing; apply the migration before shipping the new code.

Drain active generation jobs before deploying prompt changes; old workers are not snapshot-aware. Do not run local and cloud automation concurrently against the same production Airtable projects. Existing run/schedule import does not import local brief snapshots; moving such data requires a separately reviewed importer. This feature adds no implicit data import.

Rollback: drain new jobs, restore the previous app build and retain both additive tables and existing content/snapshots. Do not delete snapshots to retry or drop data as rollback. An older build ignores new metadata; it does not enforce selection/frozen guidance for future work. Retain old pack IDs and text when introducing a new guidance version so retries fail visibly if a required version is unavailable instead of silently changing meaning.
